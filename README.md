Современный информационный сайт для Республиканского инновационного туристического профессионального лицея Ак-Суу. Проект собран как имиджевый и прикладной сайт для абитуриентов, родителей, партнеров и представителей туристической отрасли Кыргызстана.

## О продукте

Сайт представляет лицей не как типичную школу или государственный портал, а как современный туристический образовательный центр. Визуальный образ строится вокруг горной природы Кыргызстана, Иссык-Куля, гостиничного сервиса, международного сотрудничества и практического профессионального образования.

Основная идея продукта: показать лицей как точку входа в туристическую индустрию региона, где студенты получают понятные профессии, практику, международный горизонт и связь с реальными работодателями.

## Позиционирование

Дизайн и подача ориентированы на баланс:

- 70% современная европейская туристическая школа;
- 20% международный образовательный центр;
- 10% государственное учебное заведение.

Вдохновение по уровню подачи:

- EHL;
- Hotelschool The Hague;
- Tourismusschulen Salzburg.

При этом сайт избегает шаблонного вида колледжа, школьного сайта или государственного портала. В интерфейсе используются крупные фотографии, много воздуха, редакционная верстка, большие заголовки, премиальная типографика и mobile-first структура.

## Целевая аудитория

- Абитуриенты, которые выбирают профессию в туризме, сервисе и гостеприимстве.
- Родители, которым важно понять надежность, условия поступления и перспективы обучения.
- Туристические компании, отели, курорты и партнеры, которым нужны подготовленные кадры.
- Представители государственных и международных образовательных организаций.
- Преподаватели и команда лицея, которым нужен понятный публичный сайт для коммуникации.

## Основные задачи сайта

- Объяснить, что такое Ак-Суу инновационный туристический лицей.
- Показать направления обучения простым человеческим языком.
- Дать абитуриентам понятную информацию о поступлении.
- Подчеркнуть практику, партнерства, международное сотрудничество и развитие до 2035 года.

Раздел для официальных новостей, объявлений, событий, публикаций и материалов о развитии лицея.

## Локальный запуск

### 1. Создать и активировать виртуальное окружение

```bash
python -m venv .venv
```

```powershell

```

```bash
pip install -r requirements.txt
```


## Деплой на Render

Проект уже подготовлен для Render. Можно деплоить двумя способами: через `render.yaml` или вручную через настройки Web Service.

### Вариант 1. Через render.yaml

Если Render увидит файл `render.yaml`, он может автоматически подтянуть настройки:

```yaml
services:
  - type: web
    name: ak-suu-portal
    runtime: python
    buildCommand: bash build.sh
    startCommand: python manage.py migrate --noinput && gunicorn myproject.wsgi:application --bind 0.0.0.0:$PORT
```

### Вариант 2. Вручную

В Render нужно создать новый Web Service и указать:

**Build Command**

```bash
bash build.sh
```

**Start Command**

```bash
python manage.py migrate --noinput && gunicorn myproject.wsgi:application --bind 0.0.0.0:$PORT
```

**Environment Variables**

```text
SECRET_KEY = сгенерировать в Render
DEBUG = 0
WEB_CONCURRENCY = 4
PYTHON_VERSION = 3.14.3
SQLITE_PATH = /var/data/db.sqlite3
```

Сайт не сохраняет заявки, сообщения формы или персональные данные. База нужна только для Django admin и управления новостями лицея. На Render желательно подключить Disk с mount path `/var/data`, чтобы изменения новостей в админке сохранялись после перезапуска и деплоя.

## Как работает build.sh

Файл `build.sh` выполняет стандартную подготовку проекта на Render:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
python manage.py collectstatic --no-input
```

То есть при деплое Render:

1. обновляет pip;
2. устанавливает зависимости;
3. собирает статические файлы.

Миграции базы выполняются в `Start Command`, потому что база для админки должна быть доступна во время запуска сервиса.

## Статика и изображения

Исходные статические файлы лежат в `static/`.

Собранные production-файлы попадают в `staticfiles/` после команды:

```bash
python manage.py collectstatic --noinput
```

В production статика раздается через WhiteNoise.

Если локально включен production-режим и CSS/JS выглядят старыми, нужно пересобрать статику:

```bash
python manage.py collectstatic --noinput
```

## Перевод

На сайте есть переключатель языков:

- RU;
- KG;
- EN.

Перевод работает через локальные словари `static/myapp/i18n/ky.json` и `static/myapp/i18n/en.json`. Основной язык контента — русский. При переключении язык сохраняется в localStorage и не обращается к внешнему Google Translate.

Важно: если текст на русском меняется в шаблонах или `myapp/views.py`, для полного перевода нужно добавить соответствующие строки в JSON-словари.

## Как обновлять контент

### Изменить текст страницы

Открыть `myapp/views.py`, найти нужную страницу в словаре `PAGES` и изменить поля `title`, `lead`, `sections` или элементы внутри секций.

### Изменить новости лицея

Новости редактируются через Django admin:

```text
/admin/
```

В разделе "Новости лицея" можно добавить новость, изменить заголовок, дату, категорию, текст, изображение, порядок вывода и статус публикации.

Для первого входа локально создать администратора:

```bash
python manage.py createsuperuser
```

### Изменить направления обучения

Открыть `myapp/views.py` и отредактировать список `PROGRAMS`.

У каждого направления можно менять:

- `title`;
- `duration`;
- `document`;
- `text`;
- `does`;
- `benefits`;
- `fit`;
- `skills`;
- `workplaces`;
- `practice`;
- `image`;
- `home_image`.

### Заменить фотографию

1. Добавить файл в `static/myapp/images/content/`.
2. Добавить путь в словарь `ASSET` в `myapp/views.py`.
3. Использовать ключ изображения в нужном блоке.
4. Выполнить:

```bash
python manage.py collectstatic --noinput
```

## Тесты

В проекте есть базовые тесты публичных страниц:

- главная страница открывается;
- все страницы из `PAGES` открываются;
- все страницы открываются и со слешем, и без слеша;
- неизвестный slug возвращает 404.

Запуск:

```bash
python manage.py test
```

## Production-настройки

В `myproject/settings.py` настроены:

- `SECRET_KEY` из переменных окружения;
- `DEBUG` через переменную окружения;
- `ALLOWED_HOSTS` с поддержкой Render;
- `CSRF_TRUSTED_ORIGINS` для production-домена;
- `STATIC_ROOT` для collectstatic;
- WhiteNoise для staticfiles.
